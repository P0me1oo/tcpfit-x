# tcpfit-x 0.16.0

按每台机器实测推导的 TCP 调优工具. 不套用固定参数, 实测 BDP 与限速器拐点.

上游 [tcpfit](https://github.com/Kylin010/tcpfit) 由 [kylin010](https://github.com/Kylin010) 编写和维护。本分支由 [P0me1oo](https://github.com/P0me1oo) 维护，新增家宽主动接入的优化线路调优。

## 安装

```bash
curl -fsSL https://raw.githubusercontent.com/P0me1oo/tcpfit-x/main/install.sh | bash
tcpfit
```

安装器校验并安装主程序和同版本优化线路调优模块。主入口为 `/usr/local/bin/tcpfit`，模块位于 `/usr/local/lib/tcpfit/<版本>/`。菜单 `1` 为国际线路调优，`2` 为优化线路调优。

从源码运行时，可在完整源码目录执行 `bash tcpfit.sh return`。单独复制一个主脚本时，优化线路调优模式需要下载对应版本的其他模块。

## 三种用法

| 用法 | 命令 |
|---|---|
| 在线运行 | `bash <(curl -fsSL .../main/tcpfit.sh)` |
| 装好后 | `tcpfit` |
| 子命令 | `tcpfit tune --role proxy --bw 500` |

## 菜单

```
   0. 退出
   1. 国际线路调优 International tuning           ~10 min
   2. 优化线路调优 Optimized route tuning
   3. 基础调优     Base tuning only                ~1 min
   4. 拐点测试     Policer sweep                   ~8 min
   5. 加 swap      Add swap (low-memory box)
   6. 查看状态     Status
   7. 端口验证     Verify port capability          ~1 min
   8. 回滚改动     Rollback all changes
   9. 检查更新     Check for updates
  10. 调优存档     Tuning archives
  11. 卸载 tcpfit
```

脚本不会自动更新. 装好之后跑的一直是装的那一版, 想升级用菜单 9 或 `tcpfit update` ——
它只检查, 发现新版本会问你要不要更新.

国际线路调优只问三个问题: 带宽、测速对端、机器用途. 确认之后跑到底不再打断.

带宽那一问支持四种输入:

| 输入 | 行为 |
|---|---|
| 数字 | 按该带宽推导缓冲区, 然后实测拐点 |
| 回车 | 现场实测带宽, 然后实测拐点 |
| `m` | 直接填限速值, 跳过拐点扫描 |
| `0` | 不做整形 |

## 子命令

```bash
tcpfit detect                                     # 机器画像
tcpfit probe    --peer <近处iperf3服务器>          # 探测可用带宽
tcpfit tune     --role proxy --bw 500             # 基础调优
tcpfit buffer   --max-mb 32                       # 自定义 TCP 收发缓冲区上限
tcpfit sweep    --peer <近处iperf3服务器> --nominal 500
tcpfit shape    --rate 510                        # 应用整形
tcpfit shape    --off                             # 移除整形, 保留基础调优
tcpfit harden   --swap 2G                         # 加 swap
tcpfit verify   --peer <近处iperf3服务器>          # 测速验证
tcpfit status                                     # 当前配置
tcpfit rollback                                   # 回滚全部改动
tcpfit update                                     # 检查更新
tcpfit archive list                               # 列出存档
tcpfit archive save "晚间配置"                     # 保存当前状态
tcpfit archive restore 0010                       # 恢复第 10 份存档
tcpfit archive rename 0010 "备用配置"              # 存档改名
tcpfit archive delete 0010                        # 删除指定存档
tcpfit uninstall --keep-archives                  # 卸载，保留存档和快照
```

## 自定义 TCP 缓冲区

以 root 执行：

```bash
tcpfit buffer --max-mb 32
tcpfit buffer --max-mb 32 --default-mb 1
tcpfit buffer --help
```

`--max-mb` 为必填项，接受 `1-1024` 的整数，单位为 MiB（1 MiB = 1048576 字节）。它统一设置 TCP 接收、发送缓冲区上限，以及 `net.core.rmem_max`、`net.core.wmem_max`。`--default-mb` 可选，用来统一设置 TCP 和通用收发缓冲区的默认值，必须为正整数且不超过上限；省略时保留各自的当前默认值，超过新上限的默认值会降到上限。TCP 最小值保持原值，最小值与请求值冲突时停止并说明原因。

命令立即应用参数，并保存到 `/etc/sysctl.d/99-tcpfit.conf`，保留文件中的其他参数。应用后会读取内核实际值核对；内核拒绝、数值不一致、保存失败或普通中断时恢复修改前的值。修改前后自动保存存档，可通过 `tcpfit archive list` 和 `tcpfit archive restore <序号>` 恢复。此命令与自动调优共用任务锁。

之后执行 `tune` 或 `return` 会重新推导缓冲区参数。需要使用指定值时，可在自动调优结束后运行 `tcpfit buffer`，再用 `tcpfit status` 查看当前配置。

## 它改了什么

| 类别 | 参数 |
|---|---|
| 拥塞控制 | `tcp_congestion_control=bbr` + `default_qdisc=fq` |
| 缓冲区 | `tcp_rmem` / `tcp_wmem` / `rmem_max` / `wmem_max` / `tcp_mem` |
| 窗口 | `tcp_window_scaling` / `tcp_moderate_rcvbuf` / `tcp_adv_win_scale` |
| 队列 | `netdev_max_backlog` / `netdev_budget` / `somaxconn` 等 |
| 连接 | `tcp_tw_reuse` / `tcp_fin_timeout` / `ip_local_port_range` 等 |
| 起步 | `tcp_slow_start_after_idle=0` / `initcwnd 32` |
| 出向整形 | HTB 全局上限 + fq 叶子 pacing |

共 32 个 sysctl 参数. 缓冲区和整形值按每台机器实测推导, 不是固定值.

## 拐点扫描怎么工作

先不限速跑一次, 看有没有东西在打你:

| 结果 | 动作 |
|---|---|
| 估算重传比低 | 未识别到限速器, 不整形 |
| 估算重传比高 | 从实测吞吐往上扫, 检查是否存在限速拐点 |
| 吞吐 > 2500 Mbit | 超出扫描上限, 不扫（可用 `--cap` 调整） |

拐点在"不限速吞吐"的**上面** —— 打穿限速器会让吞吐掉下来, 所以往上找.

## 优化线路调优

两个入口分别启动、独立完成。国际线路调优通过公共测速节点或指定对端，估测服务器出口能力并扫描限速器拐点；优化线路调优由指定测速端主动接入，测试服务器到该端的下载路径，再试调缓冲区。优化线路调优不要求先完成国际线路调优。

| 角色 | 系统 | 工作 |
|---|---|---|
| 调优端 | 常规 Linux，沿用原版的 systemd、iproute2 支持要求 | 保存和恢复配置，组织测速，推导和调整本机参数 |
| 测速端 | 常规 Linux、OpenWrt、iStoreOS | 安装缺少的 curl/iperf3，主动连接、接收数据和回报结果 |
| 测速端 | Windows，PowerShell 5.1 或 7 | 使用原生 PowerShell 和 iperf3.exe 主动接入、接收数据和回报结果 |

OpenWrt、iStoreOS 本版只支持测速端。测速脚本使用 `/bin/sh`，无需 Python，不执行 sysctl、队列、路由修改，也不启动入站测速服务。

Windows 也只支持测速端，使用独立的 `tcpfit-client.ps1`，无需 WSL、Git Bash、Python 或 curl。脚本采集到调优服务器的 TCP 握手延迟，执行 iperf3 反向下载并回报结果，不修改 Windows 网络参数或防火墙，不启动入站测速服务。

### 依赖与已有防火墙

| 角色 | 优化线路调优功能需要的工具 | 缺少时的处理 |
|---|---|---|
| 调优端 | Python 3、curl、iperf3；Python 只使用标准库 | 确认开始任务后补装缺少的工具 |
| Linux / OpenWrt / iStoreOS 测速端 | `/bin/sh`、curl、iperf3 | 接入脚本补装缺少的 curl、iperf3 |
| Windows 测速端 | PowerShell 5.1/7、iperf3.exe | 优先使用已有程序，缺少时通过 WinGet 安装 `ar51an.iPerf3` |

Windows 会依次查找 PATH、脚本所在目录和 WinGet 安装目录中的 `iperf3.exe`；从调优端直接下载执行时没有本地脚本目录。WinGet 安装后无需重开终端。使用本地脚本时，也可通过 `-IperfPath "C:\Tools\iperf3\iperf3.exe"` 指定路径。程序需要能正常运行，相关 DLL 应与发行包保持完整；缺少 WinGet、安装失败或 iperf3 无法启动时，在配对前停止并说明原因。已有可用 iperf3 时无需管理员权限。

调优端沿用 Bash、iproute2（ip、tc、ss）、sysctl、systemctl 等系统工具。国际线路调优和优化线路调优共用的任务锁需要 `flock`，通常由 util-linux 提供；缺少时提示安装并停止。安装和更新需要 curl、sha256sum。

优化线路调优模式不再要求 OpenSSL 命令行工具，不主动安装 OpenSSL、证书包或防火墙工具。Debian 的依赖准备使用 `--no-install-recommends`；系统包自身的必要依赖仍由包管理器处理。已安装的测速依赖在任务结束后保留。

调优端按现状选择端口规则的处理方式：

- UFW 已启用：复用它现有的 iptables/ip6tables，或已有的 nftables 添加临时规则，不修改 UFW 配置文件。
- 未使用 UFW，但存在生效的旧版 iptables 规则：继续用原工具，同时兼容已有的原生 nftables 输入规则。
- 其他情况：优先使用已有 nftables，其次使用对应 IPv4/IPv6 的 iptables/ip6tables。
- 没有可用工具：跳过规则管理，直接继续任务，不安装防火墙。未检测到工具并不表示端口被拦截，也可能没有启用本机防火墙；开始确认和任务记录会显示已跳过规则管理。

程序不会启用原本关闭的 UFW。已有工具的规则读取或应用失败时，会明确报告错误并清理本任务的改动，不把工具故障当成没有防火墙。测速端不安装或调用防火墙管理工具。

本机防火墙原本拦截测试端口时，程序临时放行接入端口；配对成功后，再向已配对的来源 IP 放行测速端口。任务结束时删除本任务添加的规则，恢复原来的端口访问状态。云平台安全组属于服务器外部的访问控制，需要另外允许启动时显示的两个 TCP 端口。

### 开始测试

在调优服务器选菜单 `2`，或执行：

```bash
tcpfit return
# 已知带宽时建议填写；服务器地址自动探测。
tcpfit return --server-bw 5000 --client-bw 1000
```

启动时自动探测服务器地址：优先使用实际出站路由的公网源地址，本机只有内网地址或无法取得源地址时，再查询公网出口。探测成功直接使用，不要求填写；只有探测失败才提示输入家宽可访问的 IP 或域名。也可通过 `--server` 指定地址。

启动前可填写两端标称带宽，再填写用途和测速次数，不询问端口；两端带宽都留空时自动用四连接探测。默认固定使用接入端口 **TCP 12223**、测速端口 **TCP 12224**，确认后显示实际端口，并分别生成 Linux 和 Windows 接入命令。在家宽设备上复制执行对应命令，就会自动准备环境、配对并完成测速；Windows 命令需在 PowerShell 中执行。结束后在调优端查看按配置合并的结果，输入配置序号选择，回车保存推荐配置。Linux 端缺少依赖时需要 root 权限安装。

启动时实际绑定两个端口并保留到对应服务启动；端口已被占用时明确报错退出，不自动换端口。接入服务直接接管预留套接字；iperf3 启动前释放测速端口的预留，无法启动时明确失败并清理。实际端口写入本次任务结果。已有 `--control-port`、`--iperf-port` 参数继续兼容：省略时使用上述固定端口，仅显式传 `0` 时自动选择；显式端口必须为 `1024–65535`、互不相同且未被占用。

服务器地址必须能被家宽访问；家宽无需公网 IP 或入站端口映射。`-4`、`-6` 指定测试协议族；自动探测默认使用 IPv4，仅检测到 IPv6 时自动使用 IPv6。`--yes` 跳过交互、自动探测地址并保存推荐配置，地址探测失败时退出，需用 `--server` 补充；未提供 `--server-bw` 和 `--client-bw` 时自动用四连接探测带宽。`--role proxy|bulk|mixed` 选择用途。每次评估默认测 2 次，`--repeats 2..10` 或启动时的交互输入可修改；非整数和范围外输入会在测速前被拒绝。

接入命令通过 HTTP 从调优端下载同版本的测速脚本，传递服务器地址、接入端口、测速端口和临时 token 四个参数，不嵌入程序。Linux 通过 curl 或 wget 下载 `/join.sh`，Windows 通过 PowerShell 下载 `/join.ps1` 并按 UTF-8 解码执行；开发版接入也不依赖已发布的版本标签。脚本下载、配对、控制指令和结果回报均使用明文 HTTP，不生成临时证书。

一次性随机 token 默认 600 秒有效，可用 `--token-ttl 30..1800` 设置。成功配对即撤销 token，后续会话绑定本次测速端的来源 IP。一个任务只能绑定一个测速端；再次接入会被拒绝，原任务继续。有可用防火墙工具时，临时 iperf3 端口只允许已配对的来源 IP；没有工具时保留会话配对，但不提供端口级来源限制。结束、断线或取消后停止临时服务、撤销凭据并删除本任务的规则。

在调优端按 `Ctrl+C`，会停止接入服务和正在运行的 iperf3，释放尚未交给服务的端口预留，撤销临时防火墙规则，并恢复未保存的调优改动。在测速端按 `Ctrl+C`，测速脚本会通知调优端停止；通知无法送达时，调优端通过心跳超时进入清理。等出现“端口已释放，临时防火墙规则已撤销”后再关闭终端；清理失败会保留恢复记录并提示，不会报告清理成功。

Windows 使用当前用户、当前登录会话内的任务锁，防止重复测速。普通退出会终止本任务的子进程；强制关闭 PowerShell 时，Windows 作业对象负责终止这些子进程，调优端在 45 秒心跳超时后清理。接入凭据仅保存在内存中。

两端应使用同版本脚本，每次任务都要使用本次生成的接入命令。更新调优端后重新生成命令，测速端会下载对应脚本。

iperf3 始终由家宽执行客户端 `-R`，服务器发送数据。缓冲区调优只使用单连接；两端带宽都留空时的带宽探测，以及已有全局整形的提高检查与验证使用四连接。没有家宽向服务器的大流量上传测试，也没有双向大流量测试。

### 自动流程与保留规则

优化线路调优按填写情况确定带宽参考：两端标称带宽都填时取较小值，只填一端时用该值，不额外探测；两端都留空时，先用四连接探测当前路径带宽，再用于推导 BDP。探测按指定次数测量，取接收速度中位数，沿用原有取整规则；数据不稳定、不完整或低于可推导范围时停止并恢复配置。这个实测值代表当前路径可用带宽，不表示套餐上限。候选是否保留仍由单连接速度和重传实测决定。

1. 保存本机参数、实际队列、默认路由和持久化文件，显示当前总限速、单连接限速或“未设置”，再临时解除限速，以无限速 fq 测试。仅在两端标称带宽都留空时，先执行四连接带宽探测。
2. 单独采集空载 TCP 握手延迟，不进行原始基线测速。`BDP（字节）= 带宽参考（Mbps）× 空载 RTT（毫秒）× 125`，初始收发上限按 `1.5 × BDP` 计算，不加固定余量；试调最高到 `2.5 × BDP`，取消 6 MiB 下限。普通基础调优保持原有的 `1.5 × BDP + 2 MiB` 公式、4 MiB 下限和内存范围。
3. 应用初值后开始单连接测速，每次评估测指定次数，每次 10 秒。初值结果稳定时作为后续比较参照；完整但波动明显时继续试调，先下调寻找稳定配置，以首次稳定候选建立参照。测速失败或数据缺失仍停止并恢复任务前配置。
4. 根据单连接重传和速度调整缓冲区：估算重传比 `≤1%` 即满足缓冲区重传要求，`>1%` 为高重传；`≤0.5%` 仍显示为重传优秀。四连接数据不参与缓冲区试调。
5. 测速稳定且重传不高时，候选按 **2 MiB** 递增，直到 `2.5 × BDP` 上限。高重传时先按 2 MiB 下调；尚未稳定时也先下调寻找稳定配置。效果未通过时回退、缩步，必要时反向以 1 MiB 细调。若更高候选的稳定测量出现高重传，从该候选按 **1 MiB** 向下微调，跳过已测上限，不再越过这个已知高重传边界继续上探。
6. 建立稳定参照后，**更大的候选只要测速稳定、重传不超过 1%、速度相对固定参照下降不超过 5%，就会保留**，无需提速。重传从 0% 上升到 0.8% 也可以保留；不再要求速度提高 3% 或两组速度区间完全分开。超过 1% 重传、明显测速波动或降速超过 5% 时回退到上一保留配置，再继续搜索或微调。高重传下调后有明确改善时可暂留并继续调整，但最终自动保存仍须满足 1% 重传门槛和速度保护。速度参照不会随每次保留而降低。
7. 不设试调轮数、连续无收益次数或总时长限制，持续搜索，直到到达下文规定的边界或没有可继续尝试的候选。结束后直接采用已保留配置的测速结果，最终验收也按重传不超过 1% 和固定速度参照判断。若一直没有取得稳定参照，或最终未达到重传、稳定性和速度要求，则恢复并推荐任务前配置，已完成的候选记录仍可查看和手动选择。实际参数不变时不再追加独立验收；队列变化或恢复配置后才复测。原本已有全局整形时，另行执行下文的四连接检查与验证。
8. 保存前按实际配置合并测速结果，显示普通序号和推荐标记。输入配置序号保存对应的完整参数、队列、路由及持久化状态，回车使用推荐配置。成功测完但被回退或未被推荐的候选仍可手动选择。`--yes` 自动保存推荐配置。

用于计算 BDP 的空载延迟在应用初值前单独采集，组数与指定测速次数相同。每组采集 5 个 TCP 握手样本并计算均值，再取所有有效均值的中位数，向上取整为毫秒并限制在 1～2000 ms。没有有效样本时明确使用原来的 150 ms 默认估值。后续每次测速仍采集空载和满载延迟作为记录，不重新改变 BDP 参考值。

例如，1000 Mbps、180 ms 的 BDP 为 22,500,000 字节，优化线路调优初始收发上限为各 33,750,000 字节，约 32.19 MiB，试调最高为各 56,250,000 字节，约 53.64 MiB。10 Mbps、1 ms 时计算出的初值为各 1,875 字节，上限为各 3,125 字节，不再抬高到 6 MiB。初值和上限都按整数字节向下取整。

每组的接收速度和估算重传比分别取中位数，同时检查原始数据的波动：

| 检查 | 判定 |
|---|---|
| 接收速度最大值减最小值超过中位数的 10% | 不稳定 |
| 估算重传比最大值减最小值超过 `max(0.1 个百分点, 中位数 × 50%)` | 不稳定 |
| 测速失败、数据缺失或指定次数未测完 | 未完成验证，不参与自动改善判定 |

不稳定的结果不能直接用于自动保留，也不会仅因初值波动而停止试调。初值不稳定时，以首次稳定候选建立比较参照；若它是更大的高重传候选，仍会回退，后续继续使用这组稳定速度作参照。高重传下调过程中，重传下降超过 `max(0.01, min(0.1, 比较值 × 20%))` 个百分点才视为明确改善。重传不高时优先选择满足速度保护的更大缓冲区，速度不变或小幅下降均可接受。所有重传百分比均为估算重传比，不是实际丢包率。

优化线路调优的收发上限各自最多为 `2.5 × BDP`，不再使用按总内存计算的缓冲区上限。默认值不得超过当前上限；初值很小时，TCP 参数的最小值也随默认值收小。后续下调以实际 TCP 最小值为边界，不再设 MiB 级别的最低上限。推导值超出内核整数参数范围时明确停止。

普通基础调优仍按总内存限制缓冲区，接收、发送各自适用以下范围：

| `/proc/meminfo` 中的 `MemTotal` | 自动上限允许的最大值 |
|---|---|
| 小于 448 MiB | 内存的 1/32，最低 4 MiB |
| 448 MiB 至不足 768 MiB | 收、发各 24 MiB |
| 至少 768 MiB | 内存的 1/32，最高 256 MiB |

512 MiB 档从 448 MiB 起识别，以容纳内核保留内存造成的可见总量差额。上述 24 MiB、256 MiB 范围只用于普通基础调优。两种模式的 TCP 全局内存预算仍沿用原来的物理内存比例，不随单连接缓冲区上限提高。

优化线路试调不检查可用内存、系统预留余量或缓冲区增量预算。测速失败或中断时恢复调优前配置；候选验证未通过时只回退本轮，再继续搜索。

候选不得超过 `2.5 × BDP`，到达上限时最后一步可能小于 2 MiB，不会向上取整。试调不重复测试已经试过的上限。尚未稳定或重传偏高时，附近候选测完后继续沿当前方向以 1 MiB 间隔寻找更远的未测上限，直到边界，再尝试反向。重传不高时继续按 2 MiB 向上探索；遇到已知高重传边界，只在边界下方按 1 MiB 微调。当前搜索范围没有未测候选时结束并进入保存选择。任务不受 8 轮、连续 3 轮无收益或 30 分钟总时限影响；单次测速超时、连接中断和用户取消仍触发恢复。

每轮日志显示轮次、调整原因、上限前后值、步长、单连接接收速度、估算重传比，以及暂留或回退结果。缓冲区摘要只显示收发上限。微调日志标明前一候选及微调目标，效果始终与上一保留配置比较。例如（数值仅用于展示格式）：

```text
[*] 第 1 轮，单连接：单连接重传不高，按 2 MiB 上调试探更大缓冲区；上调收发上限 24 MiB → 26 MiB，步长 2 MiB
[*] 保留配置：1 连接接收 200.00 Mbps / 估算重传比 0.000%
[*] 候选结果：1 连接接收 200.00 Mbps / 估算重传比 0.800%
[*] 本轮暂留：1 连接重传不超过 1%，速度合格，优先保留更大缓冲区；单连接，收发上限 24 MiB → 26 MiB
[*] 第 2 轮，单连接：单连接重传不高，按 2 MiB 上调试探更大缓冲区；上调收发上限 26 MiB → 28 MiB，步长 2 MiB
[*] 保留配置：1 连接接收 200.00 Mbps / 估算重传比 0.800%
[*] 候选结果：1 连接接收 240.00 Mbps / 估算重传比 1.600%
[*] 本轮回退：单连接估算重传比超过 1%，不保留更大缓冲区；单连接，收发上限 28 MiB → 26 MiB；连续无收益 1 轮，继续试调
[*] 第 3 轮，单连接：已触及高重传边界，按 1 MiB 下调微调；下调候选上限 28 MiB → 27 MiB，步长 1 MiB
[*] 保留配置：1 连接接收 200.00 Mbps / 估算重传比 0.800%
[*] 候选结果：1 连接接收 198.00 Mbps / 估算重传比 0.900%
[*] 本轮暂留：1 连接重传不超过 1%，速度合格，优先保留更大缓冲区；单连接，收发上限 26 MiB → 27 MiB
```
整形按以下规则处理，不运行完整拐点扫描。只有原本存在全局整形时，才在当前保留的缓冲区下独立测四连接，作为提高候选的参考；候选验证和提高后的最终验收也保留四连接。

| 原始状态或实测结果 | 最终处理 |
|---|---|
| 原本没有全局整形 | 不创建全局整形 |
| 指定次数的四连接吞吐未全部超过旧上限 | 恢复原整形 |
| 稳定超过旧上限，扣除原版安全余量后仍高于旧值 | 仅验证这一个提高候选 |
| 候选数据稳定、重传验证通过、四连接吞吐中位数达到候选值的 75%，且每次均超过旧上限 | 用原版整形方法持久化提高值，再作最终验证 |
| 候选未通过或最终验证未通过 | 恢复原整形，不降低旧上限 |
| 测速失败、断线、取消、异常退出 | 恢复本次尚未确认的参数和临时队列状态 |

75% 是原版“偏低但可接受”的整形吞吐档位。提高整形仍只验证一个候选，四连接重传与提高前独立测得的四连接参考数据比较，最终还要通过单连接相对固定稳定参照的 5% 速度保护、重传和稳定性检查。

为保证恢复可靠，目前识别并保存 fq、fq_codel、内核默认 pfifo_fast、noqueue、mq 及其各个叶子，以及原版的单级 HTB + fq 整形。自定义出口 filter、多级 HTB、CAKE、TBF、硬件卸载等未支持结构会在改参数前明确拒绝。单独 fq 的有限 `maxrate` 属于每流上限，测试后原样恢复，不把它当作可提高的全局整形值。

### 指标与记录

| 指标 | 来源与定义 |
|---|---|
| 吞吐 Mbps | 家宽 iperf3 `sum_received.bits_per_second`，即实际送达的 TCP 数据吞吐 |
| 重传次数 | 服务器 iperf3 `sum_sent.retransmits`，TCP 重传次数，不是丢失的数据包比例 |
| 估算重传比 | `重传次数 × 1448 / 发送字节数 × 100%`，复用原版按固定 MSS 估算的比较口径 |
| 空载延迟 | 本轮下载前，测速端到服务器控制端口的 TCP 握手耗时均值 |
| 满载延迟 | 本轮 iperf3 下载期间，同一控制端口的 TCP 握手耗时均值 |

延迟使用 curl 的 `time_connect - time_namelookup`，每次新建连接；有效样本少于三个显示“未取得”，不填零。它不是 ICMP ping，也不包含整个 HTTP 请求耗时。

保存前每组实际参数显示一行，重复测速合并为中位数。单连接和四连接分别统计；未测试的连接数不显示对应列，有限速的配置另显示限速列。例如：

| 序号 | 收发上限 MiB | 单连接 Mbps / 重传 %（中位数） | 判定 |
|---|---|---|---|
| 1 | 16/16 | 100.00 / 1.600 | 重传偏高 |
| 2 | 14/14 | 99.00 / 0.300 | 重传优秀 |
| 3 | 15/15 | 99.00 / 0.800 | 推荐 |

提示为 `选择配置序号 [推荐 3，回车确认]：`，输入表中的序号即可。同组要求实际 TCP 参数、队列和路由一致，仅存档时间或持久化文件变化不拆组；缓冲区相同但拥塞控制或限速不同的配置仍分开。

失败、跳过、不稳定和未完成的状态用简短判定显示，缺失指标显示“未取得”。至少有一次有效测速的配置可手动选择，历史判定会保留；没有有效测速的失败配置不能选择。手选时恢复该组对应的完整快照并同步持久化文件。逐次结果仍在记录目录中，结果合并不会删除原始数据。

每次任务记录位于 `/var/lib/tcpfit/return/<时间-任务号>/`：

- `before.json`：任务前的完整配置；`final.json`：实际保存或异常恢复后的完整配置。
- `idle-latency.json`：应用初值前单独采集的空载延迟，用于计算 BDP。
- `measurements/<测量标识>.json`：每次可取得的两端原始 iperf3 结果和延迟；失败或截断结果也保留诊断数据，不填零重传。
- `measurement-index.json`：所有测量序号、阶段、连接数、原始指标、状态和配置编号。即使后续失败，先前有效结果及已计划但跳过的测量也保留。
- `configurations/<快照编号>.json`：测速对应的完整参数、队列、路由、服务和配置文件快照；内部快照编号不在交互表中显示。
- `buffer-trials.json`：每轮调整原因、前后参数、实测结果、暂留或回退、失败恢复和停止原因；首次稳定候选建立参照时记录 `established_reference`；高重传后微调时记录 `refine_from_max_bytes`，说明从哪一个候选向下微调。
- `result.json`：带宽参考及来源、初值测速、单连接试调、已有整形验证、推荐和实际选择配置，以及清理结果。初值稳定时 `speed_reference` 指向 `initial_after`；初值不稳定时指向首次稳定候选 `first_stable_after`，始终未取得稳定参照则为 `null`。`buffer_search.speed_reference_round` 记录建立参照的轮次，初值为 `0`，未取得为 `null`；`after` 使用已保留试调组的数据。`configuration_options` 将显示序号关联到完整快照和逐次测量；`recommended_number`、`selected_number` 分别记录推荐与保存序号，`selected_config` 指向实际保存快照。自动探测时另记录 `path_bandwidth`，`base_kept` 只表示自动推荐对调优参数的判断。

原始 iperf3 的临时 cookie 不写入长期记录。失败、不完整数据不参与自动比较；任何阶段都不会改用公共测速节点的数据。
原版 `pre-tune.snapshot`、`0000` 快照和 `rollback` 语义保留。新增任务前后存档出现在 `tcpfit archive list` 中；通过 `tcpfit archive restore <序号>` 恢复优化线路调优存档时，会恢复完整队列、文件权限和服务状态。保留这些存档时也要保留对应的 `return/` 记录目录。

两个线路调优入口和恢复入口共用任务锁，重复启动会提示等待。普通退出自动恢复并清理；协调进程被强制结束时由守护进程恢复。若重启、只读文件系统或权限问题导致恢复未完成，下一次调优会拒绝启动，先执行：

```bash
tcpfit return-recover
```

该命令只重试当前未完成的恢复，不抢占仍在运行的任务。程序升级要同时保留主脚本、优化线路调优模块及测量端脚本；卸载会一并删除已安装模块，`--keep-archives` 继续保留配置和结果。

## 回滚

```bash
tcpfit rollback                # 按快照逐项写回, 不是恢复默认
tcpfit rollback --purge-swap   # 同时删掉 harden 建的 /swapfile
tcpfit shape --off    # 只去掉整形
```

首次改动前自动存快照到 `/var/lib/tcpfit/pre-tune.snapshot`, 记录全部 32 项参数的原始值.

0.5.7 起，原始快照同时保留为 `0000 出厂状态`，不可改名或单独删除。
`archive restore 0000` 与 `rollback` 使用同一回滚流程；“出厂状态”指首次调优前的快照。
普通存档位于 `/var/lib/tcpfit/archives/`。基础调优后自动保存，国际线路调优则在最终整形、验证完成后保存。
序号可以输入 `10` 或 `0010`；名字含空格时请加引号。

恢复普通存档会同步 sysctl 启动配置和整形服务。有路由窗口设置时沿用 networkd-dispatcher hook；
缺少该目录会提示路由只能即时恢复并返回失败。恢复失败可能已经应用部分设置，请按提示检查后重试。

`tcpfit uninstall` 默认删除存档；需要保留则加 `--keep-archives`。
若回滚失败，卸载会停止并保留存档。卸载不删除 swap、iperf3 或 ping。

swap 默认不动 —— 删掉正在用的 swap 可能让机器立刻 OOM, 要一并撤销得显式加 `--purge-swap`.

改动只落在这些文件, 不碰 `/etc/sysctl.conf`:

```
/etc/sysctl.d/99-tcpfit.conf
/etc/systemd/system/tcpfit-qdisc.service
/usr/local/sbin/tcpfit-qdisc.sh
/etc/networkd-dispatcher/routable.d/50-tcpfit-initcwnd
/etc/modules-load.d/tcpfit-bbr.conf
/var/lib/tcpfit/
```

用了 `harden --swap` 还会创建 `/swapfile` 并往 `/etc/fstab` 加一行 —— 这两个 `rollback` 默认不动,
要一并撤销加 `--purge-swap`. 缺 iperf3 时经你确认后会用包管理器安装它.

## 已知限制

- 瓶颈在国际链路而非端口时, 整形不会带来提升, 但输出看起来一切正常
- 扫满区间没找到拐点时会把区间上界当成拐点, 这种情况用 `m` 手动指定
- 需要 Linux + systemd + iproute2. OpenVZ/LXC 上 `tc` 和 `initcwnd` 可能受限
- `sweep` 需要一台近处的 iperf3 对端

## 从 nettune 升级

老机器上的产物文件名还是 `nettune-*`, 新版本会自动检测并搬迁, 快照和 rollback 都保留. 直接跑新版即可.
